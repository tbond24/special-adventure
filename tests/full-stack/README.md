# Disposable full-stack admin integration

`admin-disposable-integration.yml` runs official Supabase CLI 2.121.0 services on a fresh Linux GitHub runner, using loopback only. It needs no repository secrets or hosted project access. It never links a project, pushes a database, deploys a function, changes hosted configuration, pauses charity, or calls production. The local stack and its data volumes are removed on success, failure and workflow cleanup.

`prepare.mjs` copies the complete source migration history into ignored `work/disposable-admin/`. One **historical data assignment** in `20260906132736_operations_analytics_and_expiry.sql` is omitted: the hard-coded test operator UUID has no Auth/profile row on a fresh database. The original migration is preserved; no schema, grants or function definitions are filtered. A manifest records original/replay SHA-256 hashes and this exception. This is source-schema coverage, not evidence that production has no schema drift.

The runner creates confirmed synthetic accounts through GoTrue Admin, using only the disposable service key held in memory. All user tokens come from real password sign-in and real TOTP verification. Owner and Operator sign in, enroll and verify through actual visible frontend forms. Other denial actors use the genuine Auth API. Browser traffic is bounded independently by CSP and Playwright to the local app and local API. No REST/Auth routes are mocked, no listing DTO or backend methods are replaced, and no sessions are injected into the browser.

The real admin shell, existing sections, design preview, save/review/publish, anonymous joined public listing, desktop/mobile propagation, saved records and enquiry are exercised. Direct table/RPC denials, independent drafts, HTTP409 conflicts, transactional audit rejection, idempotent publication, restore and compiled-default rollback are checked against the real local database. A GoTrue-issued token is retained until its actual expiration and then sent unchanged to PostgREST. Twenty anonymous style timings describe this disposable environment only.

No traces, HAR files, Auth/session exports, startup logs or key files are retained. Explicit screenshots are taken only after credential and MFA dialogs close. Error text is scrubbed of generated passwords, codes, secrets and JWTs. Uploads include only sanitized JSON and named screenshots in `work/full-stack-evidence/`; inspect screenshots before presenting them as visual evidence. A failed run remains failed even if preceding checks passed. Do not label these results hosted Supabase, recovery/email-provider, production performance, production-schema parity or production deployment verification.

To run, dispatch the workflow on the development branch. Local execution is deliberately refused outside Linux CI with `VACANCY_DISPOSABLE_STACK=1`. The existing hosted verification harness remains separate; it must not be run while its test project is inactive or without a newly authorized testing window.
