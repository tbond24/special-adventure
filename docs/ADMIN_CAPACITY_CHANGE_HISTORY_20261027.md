## Behaviour and bounds

- Five statement triggers cover storage insert/update/delete, vacancy changes, room/property relationships and profile insert/delete. Profile field/heartbeat changes cannot affect the preserved capacity definition and cause no aggregate scan. Metadata size completion, unknown sizes, real zero and all storage buckets retain their existing meaning. Storage excludes database size; no quota is implied.
- Changed aggregate totals record at the server while Admin is open or closed. A bulk statement produces one observation. A normal successful source transaction records its observed state and signals the existing private Admin channel. Both record and signal roll back with the source transaction.
- A nonblocking advisory lock prevents concurrent collectors from overwriting newer observations or creating lock waits in customer actions. Contending transactions append a private transactional hint, reconciled by the clock worker after commitment. Concurrent bursts may coalesce into the latest observed state; this is not a lossless audit log of every intermediate transaction. Optional capture/delivery failures do not fail product writes and a committed hint retries capture.
- The new ten-second server clock checks a singleton next-expiry deadline/pending hint. It scans source aggregates only for pending committed changes, a due listing expiry or an hourly safety reconciliation. Clock-driven expiry is recorded at the actual observation time, not backdated to a fabricated event. The previous independent hourly job stays intact.
- The new Admin/AAL2-guarded v2 reader combines original hourly points and new observations. It retains the first real observation and the last real observation per display window, returning at most 2002 points for a 91-day range; the resolution is reported. Raw observations are preserved. Chart display windows are not collection delays. Current totals remain fresh protected reads. The v1 API remains unchanged for rollback.
- The UI accepts the v2 contract, labels Live change history, shows when change recording began and display resolution in its existing note, and retains graph/open-values state. It remains compatible with v1 hourly responses during staged preparation/rollback. Chart font, layout, metric definitions and unrelated public features are unchanged.
- Existing private current-user/AAL2 report checks, current-server live gate, reconnect catch-up, two-second UI burst batching, independent reconciliation and recent-activity/presence definitions remain. An abrupt offline departure cannot be observed before its activity timeout. Intentional feed Pause/focus rules remain.
