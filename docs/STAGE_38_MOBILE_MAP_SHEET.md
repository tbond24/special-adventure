# Stage 38 — full-screen mobile map and layered listings

## Aim, scope and acceptance

Make mobile Find feel like one spatial workspace: the map fills the viewport and an inset listings layer sits above it with visible map around its edges. The layer must support peek, browse and expanded positions without breaking map gestures, listing scrolling, pin/card synchronisation, accessibility, safe areas, themes or desktop.

Acceptance requires runtime evidence at mobile and narrow widths for all three positions, tap and handle-drag controls, empty inventory, pin selection, map movement, containment and theme contrast, followed by the full release regression and a hosted preview. Production remains unchanged until explicit approval.

## Options, value, complexity and ranking

1. Three-position bottom sheet with accessible buttons and dragging limited to the handle. Highest map/listing continuity, medium complexity, controlled gesture risk.
2. Fixed lower overlay. Lowest complexity and stable, but prevents users choosing more map or more listings.
3. One-card horizontal carousel over the map. Maximum map visibility, but poor comparison and content capacity.
4. Separate full-screen Map and List modes. Easy to reason about, but breaks the live relationship between pins and cards.

Rank: 1, 2, 3, 4. Option 1 provides the requested experience while keeping drag optional and constrained.

## Build

- Mobile map occupies `100dvh` behind the glass header, listings sheet and floating navigation.
- The inset sheet has peek, browse and expanded heights with map visible around its edges.
- The handle button toggles more/fewer listings and exposes state through accessible names and `aria-expanded`.
- A separate minimize control reaches peek without requiring a gesture.
- Vertical gestures work only on the handle and move one position per gesture.
- Listing content scrolls inside the sheet; it does not move the map or page.
- Selecting a database price pin raises a minimized sheet to browse and selects its matching card.
- Empty results start at peek; existing results start at browse.
- Expanded card mode uses one wider listing per row for easier comparison and reading.
- Reduced-motion users do not receive the height animation.

## Failure loop and score

Initial focused result: 3 passed, 6 desktop applicability skips and 3 mobile failures.

- Two containment assertions exposed an inherited `width:100%` overriding the fixed sheet's left/right insets. Ranked fixes: (1) restore `width:auto`, (2) calculate `width:calc(100% - 20px)`, (3) introduce another positioning wrapper. Fix 1 is smallest and lets the two insets remain the single source of geometry.
- The handle drag reached expanded on pointer-up, then its generated click immediately toggled back to browse. Ranked fixes: (1) suppress the single click generated by a recognized drag, (2) continuously resize on pointer-move, (3) remove drag and retain tap controls. Fix 1 preserves both interaction modes with the least event complexity.

Corrections applied; focused rerun pending.

The 390×844 visual review then found the legacy bottom-right search cluster behind the new sheet. Ranked fixes: (1) move it above the current sheet position and hide it only when expanded, (2) move search into the listings sheet, (3) return search to the top. Fix 1 preserves the existing reachable map controls and keeps search conceptually attached to the map. A geometry assertion was added so the controls cannot regress behind the browse sheet.

The first full regression returned 140 passes, 10 applicability skips and 6 failures. One was the superseded 68% map-height expectation; it now asserts the defined full viewport. One tried to open a hidden zero-result listing filter to inspect radius; it now uses the visible Map tools path. Four exposed a genuine loss of guest policy navigation because a full-screen map cannot retain a below-page footer. Ranked product fixes were: (1) compact information sheet in the map layer, (2) make the map page scroll to a footer, (3) move policies behind You. Fix 1 preserves full-screen discovery and keeps all four policies public. The failed subset and full regression must pass before advancement.

The first failed-subset rerun passed 56 with 11 applicability skips and retained one timeout because the Map tools correction had been applied to another valid Filter step in the same file. Ranked fixes were a line-specific correction, broad replacement, or forcing the hidden sheet open. The line-specific correction was applied because only this zero-result journey requires the always-visible map control.

The corrected scenario passed 2/2 across desktop and mobile. The final complete local release regression passed **147 with 11 intentional applicability skips and 0 failures**.
